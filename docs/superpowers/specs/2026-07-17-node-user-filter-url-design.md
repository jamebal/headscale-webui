# 节点用户筛选 URL 同步设计

## 背景

节点列表页目前通过组件内的 `selectUser` 保存用户筛选条件。刷新页面后该状态会丢失，用户需要重新筛选，也无法通过复制链接分享当前筛选结果。

## 目标

- 使用 `/node?user=用户名` 表达当前用户筛选条件。
- 刷新页面后恢复筛选条件并加载对应节点。
- 浏览器前进、后退或直接访问带参数的链接时，下拉框和节点列表保持一致。
- 选择 “All” 时从 URL 中移除 `user` 参数。
- 更新筛选条件时保留 URL 中其他查询参数。

## 非目标

- 不使用 `localStorage` 或 Pinia 持久化筛选条件。
- 不改变后端节点查询接口。
- 不增加新的筛选维度。
- 不调整用户管理页。

## 方案

以 Vue Router 的 `route.query.user` 作为筛选状态来源。节点列表组件把有效的字符串参数转换为用户名；缺失、空字符串或非字符串参数统一转换为空字符串，表示 “All”。

用户操作下拉框时，通过 `router.replace()` 更新查询参数。选择具体用户时写入 `user`，选择 “All” 时删除 `user`；两种操作都合并并保留现有的其他查询参数。使用 `replace()` 可以避免用户每切换一次筛选条件就产生一条新的浏览器历史记录。

组件监听规范化后的 `route.query.user`。首次挂载、直接访问链接以及浏览器前进或后退导致参数变化时，组件同步下拉框值，并使用对应用户名重新请求节点列表。URL 不发生实质变化时不重复请求。

## 数据流

1. Vue Router 解析当前 URL。
2. 组件从 `route.query.user` 得到规范化用户名。
3. 用户名同步到下拉框，并传给 `fetchNodeList()`。
4. 用户切换下拉框时，组件使用 `router.replace()` 更新查询参数。
5. 路由参数变化触发同一条同步链路，更新下拉框和节点列表。

## 边界情况

- 没有 `user` 参数：按 “All” 加载。
- `user=`：按 “All” 加载。
- 同名 `user` 参数形成数组：按非法值处理，回退到 “All”。
- URL 中的用户名暂时不在用户选项列表：仍按 URL 值请求节点，避免异步加载用户列表期间清除有效深链接。
- 节点请求失败：沿用现有行为，不覆盖已有列表；URL 仍保留用户选择，方便重试或刷新。

## 测试设计

新增针对节点筛选 URL 行为的组件测试，覆盖：

- 初始 URL 包含 `user` 时，下拉框恢复该值，节点请求携带该用户名。
- 初始 URL 不包含有效 `user` 时，按 “All” 请求。
- 选择用户时使用 `replace()` 写入 `user`，并保留其他查询参数。
- 选择 “All” 时删除 `user`，并保留其他查询参数。
- 路由查询参数变化时，下拉框与节点请求同步更新。

实现遵循现有 Vue 3、Vue Router、Vitest 和 Vue Test Utils 技术栈，不引入新依赖。
